# Offline replay and shadow decisions

```sh
rightsize replay --snapshot fixtures/replay.json
rightsize shadow --snapshot shadow.json
python3 test_replay.py
```

Both commands read only the explicitly supplied JSON file. They bypass local
configuration, provider discovery, credentials, probes, judge calls, reservations,
the live ledger and native launches. Output goes to stdout; no report file is
created unless the caller redirects it. `--account` is rejected because account
metadata belongs to the captured snapshot. Shadow consumes already captured
observations; it does not obtain fresh observations itself.

The runner uses the existing policy functions with an isolated frozen-clock
namespace. It does not change the live router's globals or implement another
routing policy. Repeated input produces identical decisions. A recommendation
is advisory: this runner does not execute the atomic ledger transaction, prove
launch identity or verify native quota freshness at a later launch time.

## Snapshot format

Version 1 shadow input contains `schema_version: 1` and a `cases` array. Each
case has exactly these fields; `fixtures/replay.json` supplies complete examples:

| Field | Meaning |
| --- | --- |
| `id`, `at` | Unique bounded case label and captured Unix timestamp |
| `task_sha256`, `context_sha256` | Exact task hash and context manifest hash, or `none` for context |
| `judgment`, `floor` | Already supplied judgment scores and minimum capability band |
| `config` | Policy fields only: bands, agents, review ladder, thresholds, reserves, slot limits, dispatch cost, effort, expensive band |
| `probes` | Captured provider buckets and redacted account metadata |
| `legacy` | Captured legacy snapshots, cooldowns, denials and reservations |
| `attempts` | Captured managed attempts, including unresolved or migrated records |

Inputs contain hashes and metadata, not credentials, skill bodies or source paths
to follow. A context hash is an identifier here, not permission to read that
context or a substitute for execution-time manifest validation. Input is bounded
to 4 MiB and 1,000 cases. Duplicate fields, nonfinite values, unsupported schemas
and malformed judgments fail with a redacted error. Keep captured account/session
metadata local; the bundled fixtures use synthetic identities only.

## Fixed baseline comparison

Replay adds `baseline` with the fixed revision `a168a85`, the SHA-256 of that
revision's `rightsize.py`, and recorded verdicts indexed by case ID. Every recorded
verdict must refer to the exact snapshot hash. Missing/extra cases, changed inputs
or a different baseline fail validation. These are recorded baseline observations,
not freshly executed baseline decisions or signed attestations of caller input.

The checked-in synthetic goldens were generated by running the original repair
baseline's policy against the same snapshots, with state access redirected to
in-memory fixtures and recording disabled. To reproduce them in a checkout that
contains that Git object:

```sh
python3 record_replay_baseline.py > /tmp/replay-regenerated.json
cmp fixtures/replay.json /tmp/replay-regenerated.json
```

This developer-only capture script reads the fixed Git object, verifies its source
hash and executes its original policy code. It does not fetch or install anything.
Production replay/shadow never loads historical code or launches this script.
Goldens store evidence, not a second production router implementation.

## Results and limits

Fifteen fixtures cover healthy quota, bucket/account denial, missing telemetry,
sticky legacy denial, legacy point/slot holds, uncertain managed work, unavailable
authentication, destructive judgment, changed account, absent native quota identity,
selected-context provenance, incomplete outcomes and a synthetic migrated legacy
record coexisting with an old hold. Migration markers do not fill missing receipts
or imply acceptance; actual migration execution is tested separately in #19. The current candidate
has zero known-denied recommendations and zero capability-floor violations. Four
selections change from the fixed baseline: uncertain managed work consumes points,
the old and migrated holds conservatively occupy both slots, and unavailable auth
or missing native quota identity causes a wait.

`changed` includes account-evidence changes; `selection_changes` compares only
status, band and provider/model/effort. Do not call every metadata change a routing
improvement. The report preserves task/context/snapshot hashes and hashed account
metadata for pairing without emitting source text.

Coverage counts all supplied attempts. Missing or mismatched native receipts stay
unresolved; an accepted label requires a matching receipt and separate review
evidence to count. Completed but unreviewed attempts remain separate. Legacy holds
are counted without inventing task/session joins. Accepted-per-attempt is `null`
when no attempts exist, not 100%. Evidence references are reported as recorded
coverage, not independently re-run acceptance checks.

Exit 0 means a valid report with no measured denial/floor violation, 1 means a
measured violation, and 2 means invalid input. None means rollout promotion.
Concurrency, lease/cancel/recovery, context attacks and protocol drift remain
covered by their focused offline suites in CI; migration proof remains #19.
No live acceptance, latency, token savings or subscription cost claim comes from
synthetic replay. The separately bounded 20-task paired pilot and rollout/rollback
gates in [EVALUATION.md](planning/EVALUATION.md) still apply.
